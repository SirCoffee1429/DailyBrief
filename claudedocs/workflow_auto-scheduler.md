## Phase 3 — Generation (FR3.1–3.6)

### Tasks
- **T3.1** Edge Function `generate-schedule`: inputs = target week + params (OT toggle,
  consistency-vs-fairness weight). Pipeline:
  1. Load roster + availability, time-off (hard blocks), coverage template + week
     exceptions, BEO demand, Live Music dates.
  2. Place **locked recurring shifts** first (§6.2 ordering).
  3. Deterministic fill of remaining slots respecting all §6.1 hard constraints
     (eligibility, training, hours cap, no double-booking, time-off, availability).
  4. Soft optimization: primary-station consistency, fair hours, full-timers toward target.
  5. Emit `schedule_data.shifts[]` in the **existing schema** (so the current grid,
     colors, edit/delete flows work untouched) + unfilled-slot report with reasons
     (optionally polished by Gemini into plain English).
- **T3.2** Persist run: draft `schedules` row (`status: draft`) + `generation_runs`
  record (params, unfilled report, duration).
- **T3.3** UI: "Build Schedule" button on SchedulePage (office) — week picker + params,
  progress state, loads draft into existing editable grid (FR3.3), unfilled-slots
  panel (FR3.4/US5).
- **T3.4** Publish flow: explicit publish action flips status; kitchen/FOH see only
  published (FR3.5, per T0.4 decision).
- **T3.5** Constraint test suite: fixture roster + template → assert zero hard-constraint
  violations across repeated runs (NFR determinism); US1/US2/US3 acceptance tests.

### Validation
- All §8 user stories pass against seeded real data.
- Generation completes in seconds for 30 emp × full week (NFR).
- Regression: manual edit/delete/color flows still work on a generated draft.

**Checkpoint 3**: owner generates a real next-week draft, compares against what they
would have written by hand, before relying on it.
